# Contributing

Homileo is a private repository. This guide is for the people working in it. For a new feature or a
change to how Homileo behaves, agree the approach first (an issue or a spec in
`docs/superpowers/specs/`) before you write it.

## Getting set up

[README.md](README.md) covers running Homileo locally and running the test suite. The per-area
notes in [packages/homileo/docs](packages/homileo/docs) explain how each part works, and
[CLAUDE.md](CLAUDE.md) lists the conventions the code follows.

## Making a change

- **Style** is checked by CI: [docs/code-style.md](docs/code-style.md). Before pushing, run

  ```sh
  npm run format && npm run sort-imports && npm run lint && npm run check
  ```

- **Tests**: add or change tests with the code. The suite runs against real Postgres and Redis,
  with `@tereo-io/sdk` test tokens (`npm run test:unit -w homileo` and `npm run test:int -w homileo`,
  or `docker/test/run.sh`).
- **Migrations** are generated by Prisma (`npx prisma migrate dev --create-only`), with raw SQL
  added only for what Prisma cannot express.
- **Version plans**: a change to `@homileo-io/sdk` or `homileo` needs one. Run
  `npm run version-plan` and commit the file it writes. CI's version-plan check says when one is
  missing ([Releases](docs/code-style.md#releases)).
- **Commit messages** follow [Conventional Commits](https://www.conventionalcommits.org/):
  `fix(sessions): …`, `feat(messages): …`, `docs: …`.

Open the pull request against `master` and fill in the template.

## What belongs elsewhere

- **App-specific chat features** (a support queue, a bot's behaviour) belong in the app, built on
  Homileo's public API. Homileo has no special cases for any app.
- **Integrations with external APIs** belong in
  [dianemo-plugins](https://github.com/dianemo/dianemo-plugins).
- **Auth, file storage, webhooks, notifications and audit** belong to tereo; Homileo reaches them
  only through `@tereo-io/sdk`.
- **UI primitives** come from [`@kosmeo-ui/react`](https://github.com/kosmeo-ui/kosmeo-ui).
