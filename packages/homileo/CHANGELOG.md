## 0.1.0 (2026-11-02)

### 🚀 Features

- Homileo's core chat API: spaces and members, join requests, sessions and direct messages, participants, messages with threads, reactions, revisions, mentions and attachments, read state and unread counts, and the OpenAPI spec. The SDK carries the resource schemas and event payloads for them. ([#2](https://github.com/homileo-io/homileo/pull/2))
- Homileo's realtime layer and catch-up: a commit-ordered events log, `GET /v1/sync` with an opaque gap-free cursor, socket.io on `/ws` with subscriptions, room fan-out by one shared audience rule, access-loss re-checks, typing and presence, and event retention. The SDK carries the event envelope, the sync response, the socket's `ready` event and the subscribe ack schemas. ([#3](https://github.com/homileo-io/homileo/pull/3))

### ⚠️  Breaking Changes

- Fixes from the second audit. Breaking: every chat mutation (spaces, sessions, members, participants, messages, reactions, attachments) now needs `homileo.spaces.write` or `homileo.chat.admin` (leaving, read state, notify and thread follow need none); `/v1/sync` message events carry the message's current view, so deleted and earlier-revision text is never replayed; `space.updated` carries `previousVisibility`; archive answers 204 to an admin who cannot read the session; `GET /sessions?externalRef=` pages; a deleted message's metadata is cleared; a busy database answers 503 instead of 500; socket errors use `server_error`. Also: Markdown parse work is budgeted and access is checked before parsing; a member-only session is readable only by those who can read its space; local sockets join rooms without a Redis round trip; sockets re-introspect their token; payload and metadata depth, attachment size and payload issue counts are bounded; provisioning uses advisory locks and an index for kind retirement; bot ids in provisioning documents are case-insensitive. New env vars: `ATTACHMENT_MAX_BYTES`, `DB_TRANSACTION_MAX_WAIT_MS`, `DB_TRANSACTION_TIMEOUT_MS`, `DB_LOCK_TIMEOUT_MS`. ([#5](https://github.com/homileo-io/homileo/pull/5))
- Fixes from an audit of the realtime, chat and platform layers. Breaking: webhook events of private sessions (space-less, or `access` `members`) now use `homileo.private_*` types that need the new `homileo.messages.read_private` permission; `TEREO_SERVICE_SLUG` accepts only `homileo`; `/v1/sync` refuses a `since` cursor past the current transaction. Also: realtime events follow current access (mentions, join requests to moderators, created events to their founders, deletes to mentioned readers), bounded Markdown parsing, a 50-emoji reaction cap, attachment keep recovery, `/me/mentions` paging, message-type retirement serialized against posts, partial indexes, and DM and join-request fixes. The SDK caps a provisioning document's version at 64 characters and lists the private webhook event names. ([#4](https://github.com/homileo-io/homileo/pull/4))
- Homileo's foundation: the service skeleton with its env, errors, Prisma schema and baseline migration; principals and `GET /v1/me`; provisioning documents for space kinds and message types; `recordChange` with daily event partitions; the access policy module; the worker role; and Homileo's declaration to tereo (`tereo-provisioning.json`). The SDK carries the event registry and the provisioning document types and JSON Schema. ([#1](https://github.com/homileo-io/homileo/pull/1))
- Fixes from the third audit. Breaking: every `/v1` route and the socket handshake need `homileo.spaces.read` (write and `homileo.chat.admin` include it), except leaving and muting (`DELETE` of the caller's own member or participant row, `PUT /sessions/:id/notify`), so a principal whose read was revoked can step out; `POST /principals/resolve` needs write; space moderators may archive, remove participants from and delete messages in `access: members` sessions they cannot read (204, no content); `DELETE /messages/:id` can answer 204; mention readers in space sessions must be able to read the space through membership or participation (deliberately, a grant moderator who is not a space member is not mentioned); body-parser 415s answer 400; tereo library errors answer `server_error`; deadlocks answer 409 `version_conflict`; new socket code `temporarily_unavailable` and server event `unsubscribed`; validation errors list at most 20 issues. Also: edits no longer re-parse earlier revisions (new `message_ever_mentions`), Markdown lazy lines are budgeted, `/sync` keeps stored reaction summaries and caps rows scanned per page, member removal records its events in one batch, list-order indexes, bounded provisioning lock waits, busy-database 503s for connection timeouts, no bearer token in cross-node socket fetches, sweep-based room repair, attachment size enforced by the keep job and pending placeholders capped, mention emails capped and cooled down, `/me/mentions` judges stored mentions as `/sync` does, deep list pages seek, event ids are paired with their rows by key. New env vars: `ATTACHMENT_MAX_PENDING`, `MENTION_EMAIL_COOLDOWN_SECONDS`. SDK: messages, reaction routes and `reaction.added`/`reaction.removed` carry `reactionSeq` (the reaction events also the whole summary), and clients keep the summary with the highest; `SocketUnsubscribedSchema` describes the `unsubscribed` event. ([#8](https://github.com/homileo-io/homileo/pull/8))
