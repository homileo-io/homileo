# OpenAPI Specification Management

The spec is created in plan 2 (*Core chat API*); until then `packages/homileo/openapi/` does not
exist. This skill is the structure it follows (the same as tereo's): one service, **one spec**,
split by area into files.

## Directory Structure

One root, one bundle and one Redocly config (`packages/homileo/redocly.yaml`):

```
packages/homileo/
├── redocly.yaml                  # Rules, root openapi/openapi.yaml → output openapi/bundled-openapi.yaml
├── .redocly.lint-ignore.yaml     # Lint problems skipped on purpose, if any
└── openapi/
    ├── openapi.yaml              # The root — info, servers, security, tags, x-tagGroups, path $refs, components, webhooks
    ├── bundled-openapi.yaml      # Generated by `npm run openapi:build` — don't hand-edit
    ├── components/
    │   ├── headers.yaml          # Retry-After, X-RateLimit-*
    │   ├── parameters.yaml       # CursorParam, LimitParam, SortParam, SortDirParam, …
    │   ├── responses.yaml        # Unauthorized/Forbidden/NotFound/BadRequest/Conflict/RateLimit/ServerError/NoContent
    │   ├── security.yaml         # BearerAuth
    │   ├── webhook-schemas.yaml  # The webhook event envelope and delivery headers
    │   └── <area>/               # parameters, responses, schemas for spaces, sessions, messages, events
    └── paths/
        ├── platform/             # /health, /v1/me
        ├── spaces/  sessions/  messages/  events/    # one file per resource
```

### Shared and area components

A component every area uses the same way is defined once in `components/*.yaml`. Where an area's
version differs — a different `limit` range, a different error-code enum — it is a separate
component in `components/<area>/`, prefixed with the area (`MessagesLimitParam`,
`SessionsNotFoundResponse`). Use the area's variant when one exists. Never widen a shared component
unless it is true of every route that references it. Component names and `operationId`s must be
unique across the whole spec: Redocly's bundler hoists every component by its name.

### Paths carry the full mount prefix

The spec keys every path by its **full** URL, so there is one server, `http://localhost:4101`:
`/v1/spaces/{spaceId}`, `/v1/sessions/{sessionId}/messages`, `/v1/sync`. Health is `GET /health` at
the root. Descriptions that mention another route use the full path too.

### Tags

Every operation has a tag, and every tag belongs to one `x-tagGroups` entry (Spaces, Sessions,
Messages, Events, Platform), which Redoc shows as sections (a tag in no group is hidden). Tag names
are unique across areas.

## Spec Version and Conventions

- **OpenAPI 3.1.0**, `info.version` the service's version.
- All `$ref`s are relative: `'../../components/<area>/schemas.yaml#/SchemaName'` or
  `'../../components/responses.yaml#/NotFoundResponse'` from `paths/<area>/`, `'#/SchemaName'`
  inside a component file.
- Path refs in the root use JSON-pointer escaping:
  `'./paths/sessions/sessions.yaml#/~1v1~1sessions'` (`/` → `~1`).
- **Examples**: `examples:` (array), not `example:`.
- **Nullable fields** — one style everywhere: `type: [string, 'null']` for a scalar (keep `format`,
  `maxLength` etc. alongside), `oneOf: [{ $ref: '#/X' }, { type: 'null' }]` for a ref. Never
  `nullable: true` (a 3.0 keyword that 3.1 tooling ignores).
- **Pagination is cursor-based**: a limit param + `CursorParam` + a sort param + `SortDirParam`, and
  list responses are `{ data, hasMore, limit, nextCursor }`. Messages and `/sync` page by `seq` /
  event id (`since`, `before`, `after`) as the spec says; follow the design spec's *API* section.
- **Errors** are `{ error, error_description, ...details }`; document each operation's codes.
- **Organization**: every operation outside `/health` is limited to the caller's organization; a
  token without an organization (`org_id`) gets 400 `organization_required`; no header names one.
  Say so once in the root description, not per operation.

### Security

The root sets `security: [BearerAuth: []]`, and `redocly.yaml` makes `security-defined` an error. An
operation without a `security:` block inherits `BearerAuth`, so **every public operation must say
`security: []`** — `GET /health`, and every webhook definition (they describe outbound deliveries,
which carry no bearer token).

An operation states its permission with a **Required permissions** block in the description
(`homileo.spaces.read`, `homileo.spaces.write`, `homileo.chat.admin`, or a kind's grant such as
`support.cases.read`) **and** the access rule that applies ("the caller must be able to read the
session"). Permission names are tereo's dotted, hierarchical form (`write` ⊃ `read`, `admin` ⊃ all).
A resource the caller cannot read is a **404**, not a 403 — document it that way.

### Archive and provisioning conventions

- `archivedAt` is a **nullable date-time**; list operations take `includeArchived` (boolean,
  default false) where the resource archives.
- Rows that came from provisioning are read-only: document `409 managed_by_provisioning` on every
  mutating operation of a provisioned resource (space kinds, message types).
- A deleted message has an empty `body` and `deletedAt`; revisions stay.

## Root openapi.yaml Pattern

```yaml
openapi: 3.1.0
info:
  title: Homileo API
  version: 0.1.0
  description: |
    {Overview of the areas, Authentication (tereo tokens), Organizations, Permissions and access,
     Pagination, Error handling, Realtime and /sync, Webhook deliveries}

servers:
  - url: http://localhost:4101
    description: Local development server (each app deploys its own Homileo; substitute its host)

security:
  - BearerAuth: []

tags:
  - name: {Tag}
    description: {Description}

x-tagGroups:
  - name: Sessions
    tags: [...]

paths:
  /v1/sessions:
    $ref: './paths/sessions/sessions.yaml#/~1v1~1sessions'

components:
  securitySchemes:
    BearerAuth:
      $ref: './components/security.yaml#/BearerAuth'
  parameters: { … }
  responses: { … }
  schemas:
    Session:
      $ref: './components/sessions/schemas.yaml#/Session'

webhooks:            # every webhook event type
  homileo.message.created:
    $ref: './paths/messages/webhook-events.yaml#/homileo.message.created'
```

## Path File Pattern

```yaml
/v1/sessions:
  get:
    tags: [Sessions]
    summary: List sessions
    description: |
      Returns the sessions the caller can read in their organization.

      **Required permissions:**
      - `homileo.spaces.read`

      **Filter fields and operators:** …
    operationId: listSessions
    security:
      - BearerAuth: []
    parameters:
      - $ref: '../../components/sessions/parameters.yaml#/SessionsLimitParam'
      - $ref: '../../components/parameters.yaml#/CursorParam'
    responses:
      '200':
        description: Paginated list of sessions
        content:
          application/json:
            schema:
              $ref: '../../components/sessions/schemas.yaml#/ListSessionsResponse'
      '400': { $ref: '../../components/responses.yaml#/BadRequestResponse' }
      '401': { $ref: '../../components/responses.yaml#/UnauthorizedResponse' }
      '403': { $ref: '../../components/responses.yaml#/ForbiddenResponse' }
      '429': { $ref: '../../components/responses.yaml#/RateLimitResponse' }
      '500': { $ref: '../../components/responses.yaml#/ServerErrorResponse' }
```

Say in the description which event an operation records ("A `session.created` event is recorded,
and the `homileo.session.created` webhook is emitted."). Ids are UUIDs (`format: uuid`).

## Schema Pattern

```yaml
Session:
  type: object
  description: A 1-on-1 or group chat, in a space or on its own
  required: [id, organizationId, kind, createdAt]
  properties:
    id: { type: string, format: uuid, description: Unique identifier }
    spaceId:
      type: [string, 'null']
      format: uuid
      description: The space it belongs to; null for a DM or ad-hoc group
    archivedAt:
      type: [string, 'null']
      format: date-time
    createdAt: { type: string, format: date-time }

ListSessionsResponse:
  type: object
  properties:
    data: { type: array, items: { $ref: '#/Session' } }
    hasMore: { type: boolean }
    limit: { type: integer }
    nextCursor: { type: [string, 'null'] }
```

## Webhook Definition Pattern

Each event type that the SDK registry flags as a webhook is documented in the area's
`webhook-events.yaml` and referenced from the root's `webhooks:` section. It is keyed by the tereo
event type (`homileo.<area>.<verb>`). The body is tereo's webhook envelope with `eventType`
(a `const`), `entityType`, and `data: { eventId, ...payload }` taken from the event's Zod schema in
`@homileo-io/sdk` — the spec's schemas and the SDK's must agree. Deliveries come from tereo, signed
by tereo; point at tereo's documentation for the headers and signature rather than repeating them.

```yaml
homileo.message.created:
  post:
    tags: [Messages]
    summary: Message created
    operationId: webhookMessageCreated
    requestBody:
      required: true
      content:
        application/json:
          schema:
            allOf:
              - $ref: '../../components/webhook-schemas.yaml#/WebhookEvent'
              - type: object
                properties:
                  eventType: { const: homileo.message.created }
                  entityType: { const: Message }
                  data: { $ref: '../../components/messages/schemas.yaml#/MessageCreatedEventData' }
    responses:
      '2XX':
        description: Any 2xx response acknowledges the delivery; anything else is retried.
```

The event type must exist in the SDK's `EVENT_TYPES` and in Homileo's tereo declaration (see the
`outbox` skill).

## Common Response Patterns

| Status | Use | Component |
|--------|-----|-----------|
| 200 | GET single, PATCH, POST actions | Resource schema |
| 201 | POST create | Resource schema |
| 204 | DELETE, archive/restore with no body | `NoContentResponse` |
| 400 | Validation errors, `organization_required` | `BadRequestResponse` |
| 401 | Missing/invalid token | `UnauthorizedResponse` |
| 403 | Insufficient permission | `ForbiddenResponse` |
| 404 | Not found **or not readable by the caller** | `NotFoundResponse` |
| 409 | Conflict, `managed_by_provisioning`, archived | `ConflictResponse` |
| 429 | Rate limit exceeded | `RateLimitResponse` |
| 500 | Server error | `ServerErrorResponse` |

## Linting & Bundling

From `packages/homileo` (`@redocly/cli` is a dev dependency; both read `redocly.yaml`):

```bash
npm run openapi:lint    # lint the spec — CI runs this (from plan 2)
npm run openapi:build   # lint, then regenerate openapi/bundled-openapi.yaml
```

The bundle is committed: run `openapi:build` after editing the spec and commit the result. Keep its
path, `openapi/bundled-openapi.yaml` — consumers such as the standalone UI read it from there.
`redocly.yaml` extends `recommended`, turns `no-server-example.com` and `info-license-strict` off
(the repo is private and unlicensed), and makes `security-defined` an error.

## When to Update

- **New endpoint added** → path file + root `openapi.yaml` `paths:` entry
- **Request/response schema changed** → `components/<area>/schemas.yaml` (+ root `components.schemas` ref)
- **New model** → schema + Create/Update request + `List…Response`
- **Permission or access rule changed** → the operation's Required permissions block and the root description
- **New webhook event** → definition in the area's `webhook-events.yaml` + root `webhooks:` entry,
  the SDK registry, and the tereo declaration
- **New resource group** → new path file under `paths/<area>/`, referenced from the root, with a tag
  in an `x-tagGroups` entry
- **Route removed** → remove it from the path file and the root

Then `npm run openapi:build`.

## Source of Truth

- **Zod schemas** — `src/routes/**/schemas.ts` — define request validation; the SDK's event schemas
  define event payloads
- **Controllers** and the Prisma schema define response shapes and what is stored
- **Route files** — `src/routes/**/index.ts` — define which paths and methods exist
- **`src/policy/`** — the access rules the descriptions state
- **The OpenAPI spec** must match all of the above — keep them in sync
